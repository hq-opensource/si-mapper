<decisions>
## Implementation Decisions

### Graph visualization library
- Use **Sigma.js** (`@react-sigma/core`) + **ForceAtlas2** layout (`graphology-layout-forceatlas2`)
- Stronger long-term choice over react-force-graph-2d: better interactivity, richer layout algorithms, WebGL rendering via SigmaContainer
- Graph data is managed via `graphology` as the underlying data structure
- Layout: ForceAtlas2 runs automatically on mount to cluster nodes naturally

### Node interactions
- **Hover effect**: when the user moves the mouse over a node, a floating info card appears in the bottom-right corner of the canvas showing the node's RDF properties (type, label, ID, connected node count)
- **Click**: clicking a node locks the info card visible (same card, stays until user clicks elsewhere) AND highlights all inbound + outbound connections and the nodes at their other ends (everything else dims)
- **Drag**: clicking and holding a node lets the user drag and reposition it on the canvas (standard Sigma.js drag behavior)

### Zoom-triggered label visibility
- Node labels and edge labels are **zoom-dependent**: they do not all render at once
- Nodes with more connections (higher degree) have larger visual size and their labels are visible from further out
- Medium nodes become labeled at medium zoom
- Low-degree / leaf nodes only show their label when zoomed in close
- This is implemented using Sigma.js's built-in `zoomShowLabels` and size-based rendering with graphology node degree as the size metric
- Edge labels use the same principle: shown on hover, or when sufficiently zoomed in

### Node display
- Node label = **RDF local name** (namespace stripped): e.g., `Fan-SF1`, `Duct-Primary-01`
- Node **color-coded by `rdf:type`**: each distinct RDF type gets a unique color (the planner should define a sensible HVAC-appropriate palette: e.g., Equipment = blue, Duct = green, ConnectionPoint = orange, System = purple, etc.)
- Node **size scales with degree** (number of connections) — highly connected nodes are larger and more prominent

### Edge display
- Edge labels = RDF predicate local name (namespace stripped)
- Zoom-triggered: visible at close zoom levels, hidden when zoomed out
- Edges are directed (arrows) following the RDF subject→predicate→object direction

### TTL import tool
- New master agent tool: `load_ttl_to_neo4j(tool_context) -> dict`
- **Replace strategy**: every call wipes Neo4j and reimports from the current `ontology.ttl` — no append, no merge, clean state
- Import uses Neosemantics (`n10s.rdf.import.fetch`) to load the TTL file
- The master agent decides when to call this (HITL-triggered, same pattern as other Phase 9 tools)
- Tool returns `{"status": "success", "node_count": N, "relationship_count": M}` or error dict

### Frontend Graph tab layout
- Full-screen canvas — Sigma.js fills the entire tab area (same as View/Edit iframes)
- Toolbar overlaid on top of the canvas: zoom in, zoom out, reset layout, toggle ForceAtlas2 run/pause
- Node info card: bottom-right corner overlay, appears on hover, locks on click

### Docker / Neo4j infrastructure
- Add `neo4j` service to the **existing `docker-compose.yml`** with a new profile (e.g., `graph`)
- Use **standard port mapping** (not `network_mode: host`): `7474:7474` (HTTP browser), `7687:7687` (Bolt)
- Neo4j image: `neo4j:5` + Neosemantics plugin pre-installed (use `neo4j:5` with plugin env var or custom image)
- Credentials: `NEO4J_AUTH=neo4j/neo4j_password` (store in an env file, e.g., `neo4j/neo4j.env`)
- The Next.js API route connects via Bolt (`neo4j://localhost:7687`) using the official `neo4j-driver` npm package
- The Python agent tool connects via `neo4j` Python driver (or HTTP API) to Bolt port

### Next.js API route
- Route: `GET /api/graph` — queries Neo4j for all nodes and relationships, transforms to `{ nodes: [...], edges: [...] }` format consumable by Sigma.js / graphology
- Node shape: `{ id, label, type, properties: {...} }`
- Edge shape: `{ id, source, target, label }`
- The frontend `GraphWindow.tsx` calls this route on mount and whenever the graph tab becomes active

### Claude's Discretion
- Exact ForceAtlas2 parameter tuning (gravity, scaling ratio, barnesHut optimization)
- Color palette assignment for specific RDF types (planner should look at the actual TTL types from the 223P ontology)
- Neosemantics configuration constraints (uniqueness, handle vocabulary)
- Neo4j indexing strategy for query performance

</decisions>
