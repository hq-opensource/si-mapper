<objective>
Implement the `graphdb` backend mode using Ontotext GraphDB Free as the
graph database.

This step introduces **completely new, independent tools** — no existing Neo4j
tool is modified.  The two new Python modules mirror the interface of the
existing Neo4j tools so the master agent can call them identically.  Tool
registration in `create_master_agent.py` is gated on `GRAPH_BACKEND` so only
one set of tools is active at runtime.

The frontend graph visualization (`GraphWindow.tsx` / Sigma.js) is **reused
without modification** by making the existing `/api/graph/route.ts` return
the same `{nodes, edges}` JSON shape from a GraphDB SPARQL query.  An
optional "Open in GraphDB Workbench" link can be added to the Graph tab
toolbar using `GRAPHDB_PUBLIC_URL`.

## UI Strategy for `graphdb` mode

**Recommended approach: server-side SPARQL → same `{nodes, edges}` JSON**

The existing `GraphWindow.tsx` component (Sigma.js + ForceAtlas2) consumes
`{nodes: [...], edges: [...]}` from `/api/graph`.  A new branch in that
route translates a SPARQL SELECT query result into the same shape.  Zero
frontend component changes are needed; the Sigma.js graph renders the
ontology regardless of whether data came from Neo4j Cypher or GraphDB SPARQL.

SPARQL query used to fetch the full graph:
```sparql
SELECT ?s ?p ?o WHERE { ?s ?p ?o . FILTER(isIRI(?o)) }
LIMIT 5000
```
Subjects become nodes, predicates become edge labels, objects become target
nodes.  Subject and object local names derive from the URI (same `localName()`
helper already in the route).

The optional workbench link is rendered in the Graph tab toolbar as:
```
🔗 Open in GraphDB Workbench
```
visible only when `NEXT_PUBLIC_GRAPHDB_PUBLIC_URL` is set.  This gives power
users direct access to GraphDB's Visual Graph, SPARQL editor, and inference
explorer without duplicating that functionality in the custom UI.
</objective>

    ```
    6. Clear existing statements:
         DELETE {base_url}/repositories/{repo_name}/statements
         Accept 204 or 200; raise on other status.

    7. Upload TTL:
         POST {base_url}/repositories/{repo_name}/statements
         Content-Type: text/turtle; charset=UTF-8
         body = ttl_content (UTF-8 encoded bytes)
         Accept 204 or 200; raise on other status.

    8. Count triples (estimate):
         GET {base_url}/repositories/{repo_name}
         Accept: application/sparql-results+json
         ?query=SELECT (COUNT(*) AS ?cnt) WHERE { ?s ?p ?o }
         Parse result → return cnt.

    9. Return:
         {"status": "success", "repository_name": repo_name,
          "triples_loaded": <int>, "base_url": base_url}
    ```

    ```python
    ROW_LIMIT = 500

    def _get_graphdb_config() -> tuple[str, str]:
        """Returns (base_url, repo_name) — repo_name requires tool_context."""
        base_url = os.getenv("GRAPHDB_REST_URL", "http://localhost:7200").rstrip("/")
        return base_url

    def _run_sparql_query(base_url: str, repo: str, query: str) -> dict:
        try:
            resp = requests.get(
                f"{base_url}/repositories/{repo}",
                params={"query": query},
                headers={"Accept": "application/sparql-results+json"},
                timeout=30,
            )
            resp.raise_for_status()
            bindings = resp.json().get("results", {}).get("bindings", [])
            rows = [{k: v["value"] for k, v in b.items()} for b in bindings]
            truncated = len(rows) > ROW_LIMIT
            return {"query": query, "result": rows[:ROW_LIMIT], "error": None,
                    "truncated": truncated}
        except Exception as e:
            return {"query": query, "result": None, "error": str(e)}
    ```
